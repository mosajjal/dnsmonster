# dnsmonster documentation

The documentation site for [dnsmonster](https://github.com/mosajjal/dnsmonster), built with
[Astro](https://astro.build) and [Starlight](https://starlight.astro.build), styled with Tailwind CSS
v4 and [shadcn/ui](https://ui.shadcn.com) on the Fenko Security design system.

The `main` branch is published at [dnsmonster.dev](https://dnsmonster.dev).

## Running locally

```sh
npm install
npm run dev      # http://localhost:4321
```

Other commands:

| Command | Does |
| --- | --- |
| `npm run build` | Build the static site into `dist/` |
| `npm run preview` | Serve the built site locally |
| `npx astro dev --background` | Run the dev server detached (`astro dev stop` / `status` / `logs`) |

## Layout

```
src/
  content/docs/     # every documentation page (md / mdx)
  components/       # Hero, Features, StatBand, OutputGrid, StageBadge, PageTitle override
  components/ui/    # shadcn/ui primitives (button, card, badge, separator)
  styles/global.css # Fenko design tokens, Starlight overrides, Tailwind theme
  assets/           # logo variants
public/             # favicons and diagram images, served as-is
astro.config.mjs    # site config and sidebar
```

## Writing pages

Pages live in `src/content/docs/`. Frontmatter is Starlight's — `title`, `description`, and
`sidebar.order` for position within a section. Sidebar sections are defined in `astro.config.mjs`;
everything except "Getting started" and "Reference" is autogenerated from its directory.

There is no separate landing page. The site root (`src/content/docs/index.mdx`) is the "Getting
started" overview, and it carries the hero.

Set `hideTitle: true` in frontmatter on any page that opens with the `<Hero />` component, so the
hero headline is the page's only `h1`.

## Design system

Colours, typography and spacing follow the Fenko Security brand: Fennec Amber (`#F5A623` dark /
`#D4920A` light) on graphite neutrals, Saira for UI and headings, JetBrains Mono for code. Dark is
the default theme; light is fully supported. All tokens are defined in `src/styles/global.css` — edit
them there rather than hardcoding colours in components.

## Prose linting

`.vale.ini` and `vale-styles/` configure [Vale](https://vale.sh) with the Microsoft style guide:

```sh
vale src/content/docs
```
